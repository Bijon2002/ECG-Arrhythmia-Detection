4.4 Temperature Calibration Results 
Each of the five ensemble models was independently calibrated using Temperature Scaling applied 
to a 2,000 sample subset of the test dataset. The results presented in Table 3.5 demonstrate that all 
five models exhibit overconfidence in their raw SoftMax outputs, as is typical for modern deep 
learning architectures (Guo et al., 2017). 
The mean optimal temperature value of around 1.207 signifies a moderate degree of 
overconfidence in the models' confidence estimates. The spread between 1.032 and 1.306 
corresponds to the variance introduced by independent model initialization - each path of 
convergence leads to a model of different level  of overconfidence. Importantly, each model's 
individual calibration via temperature scaling means that each ensemble member will have its 
overconfidence independently corrected, resulting in an ensemble with a calibrated mean 
probability distribution. 
Improvement in the calibration can best be quantified by the Expected Calibration Error (ECE) 
metric, which gauges the difference between model confidence and accuracy over confidence bins. 
Prior to calibration (with T=1.0 for all models), raw SoftMax outp ut exhibits systematic 
overestimation of confidence, especially in the high -confidence bin (>90% confidence). The 
temperature scaling helps close the gap, moving the reliability graph toward the line of perfect 
calibration. Although the expected calibratio n error was not calculated in the current 
implementation for time constraints, the effect is widely known to take place for this kind of 
networks (Guo et al., 2017) and is shown qualitatively by the temperatures being above 1.0.

4.5.2 Cluster-Based Entropy in Context 
 
The Cluster-Based Entropy (CBE) method provides a complementary uncertainty signal during 
API inference that is particularly sensitive to clinically significant ambiguity. When a heartbeat's 
probability mass is distributed across the Normal cluster and the  Ventricular/Fusion cluster - a 
configuration that is clinically alarming, as it suggests the model cannot determine whether the 
beat is benign or potentially dangerous - the CBE will be high even if the standard Predictive 
Entropy remains moderate. 
For example, consider a hypothetical beat with ensemble -averaged probabilities: P(N)=0.45, 
P(S)=0.05, P(V)=0.35, P(F)=0.10, P(Q)=0.05. The Predictive Entropy of this distribution is 
approximately 1.3 nats, which is high. The CBE, computed on the cluster pr obabilities q = [0.45, 
0.05, 0.45, 0.05], is approximately 1.0 nats - also high, and more importantly, it correctly captures 
the clinical ambiguity: the model is uncertain between a Normal beat and a ventricular-origin beat, 
which is precisely the kind of uncertainty that should trigger clinical review. A threshold of CBE 
> 0.5 is used in the API to flag such cases. 
4.5.3 CBE vs Standard Predictive Entropy: A Mathematical Comparison 
 
Standard Predictive Entropy (PE) is defined as H(p) = -Σᵌ pᵌ log pᵌ, summed over all K classes. It 
treats each class as equally distant from every other. For a five -class distribution, a beat with 
probability mass split equally between Normal (N) and Ventricular (V) produces the same entropy 
as one split equally between Supraventricular (S) and Fusion (F) — yet these two situations carry 
very different clinical risk. 
Cluster-Based Entropy (CBE) addresses this by first projecting the five-class probability vector p 
∈ R⁵ onto a four-dimensional cluster vector q ∈ R⁴, where each cluster aggregates classes that share 
a clinical risk profile: q₁ = p(N), q₂ = p(S), q₃ = p(V)  + p(F), q₄ = p(Q). CBE is then computed as 
H(q) = -Σ_j q_j log q_j  over the four clusters. Because the Ventricular and Fusion classes are 
aggregated into a single high -risk cluster, ambiguity between V and F does not inflate the CBE 
score — only ambiguity between clinically distinct risk categories does. 
=== PAGE 64 ===
 
Page 64 
For the example distribution P(N)=0.45, P(S)=0.05, P(V)=0.35, P(F)=0.10, P(Q)=0.05, standard 
PE ≈ 1.31 nats and CBE ≈ 1.02 nats . Both are high, correctly flagging uncertainty. However, 
consider a distribution P(N)=0.45, P(S)=0.05, P(V)=0.30, P(F)=0.15, P(Q)=0.05: standard PE is 
unchanged (≈1.31 nats) since only V ↔F mass shifted, but CBE remains ≈1.02 nats because the 
V+F cluster total is unchanged. The CBE correctly does not escalate this case further, since the 
shift between V and F within the same clinical cluster is not clinically meaningful. This behaviour 
is precisely the advantage of CBE over raw Predictive Entropy: it escalates cases that matter 
clinically and remains stable for shifts that do not.

4.6.2 Limitations 
Several limitations of the current approach should be noted. 
 
• Training epochs: The number of training epochs allocated to all the five ensemble members 
equals five. Though the curves of convergence of loss functions (Table 4.2) show that there 
is some learning going on during the process, one can expect that the system could benefit 
from a longer training procedure, possibly up to 50+ epochs with early stopping on the 
validation set. However, the five -epoch training was used in order to guarantee the 
reproducibility of the project within its timeline. 
 
• Fusion class performance: Although there is a considerable boost in the performance of the 
classifier compared to the baseline with one model, the F1 -score of 0.59 for the Fusion 
class is still not enough for the deployment in the clinical setting without human 
supervision. This is essentially a data problem – the system was exposed to too few cases 
of Fusion class beats in both training and testing sets – there are only 160 of those in the 
=== PAGE 66 ===
 
Page 66 
test set. Data augmentation or oversampling targeting specifically the Fusion class should 
be considered in this case. 
• Evaluation of the system on a single dataset: All results were produced by training and 
testing the system on the MIT -BIH dataset. Thus, the results are an internal validation of 
the system and have not been tested on any other independent data yet. It is essential to 
carry out cross -dataset validation on, for example, the PTB -XL or INCART datasets to 
check how well the features are generalised across different patients and ECG devices. 
 
• MC Dropout threshold: The uncertainty threshold of 0.02 for the MC Dropout method was 
determined by the analysis of the empirical distribution of the variances on the 50-beat test 
set. The threshold could be determined more accurately, for example, by usin g a ROC -
curve analysis on the dedicated calibration set. 
 
 
• Computational overhead: The True Deep Ensemble adds fivefold overhead on the 
inference time. Even though there are no noticeable delays in the batch processing mode, 
such overhead would cause problems for real-time continuous processing of multi-channel 
ECGs. Model compression should be carried out for deploying the model on edge 
computing devices.
